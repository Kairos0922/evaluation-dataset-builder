# 评测数据集质量评价标准

**标准版本：** 2.0.0  
**适用版本：** Evaluation Dataset Builder 0.0.2  
**状态：** 方法论标准；综合评分模型尚未验证。

## 1. 基本原则

评测集质量是对特定用途和适用范围的判断，不是脱离目标的固定属性。质量评价必须回答：该数据集是否能够支持声明的评测目标和决策，以及我们有什么证据支持这一判断。

本标准适用于通用 Agent / Skill，支持：
- Capability Evaluation：测量目标能力及其差异。
- Regression Evaluation：发现版本变化引入的退化和已知失败。

必须区分两条评价路径：
1. **Independent Dataset Assessment（IDA）**：不运行被测 Agent，独立检查数据集设计、内容、来源、目标对齐、覆盖和判定契约。
2. **Empirical Runtime Assessment（ERA）**：在精确绑定的 Agent/Skill、模型、Harness、工具和环境中运行，评价评分器质量、测量效力、故障检出、稳定性和统计不确定性。

IDA 与 ERA 的结果分别报告，不得互相替代。

## 2. 关键门禁

以下门禁采用 PASS / FAIL / UNKNOWN / NOT_RUN / NOT_ASSESSED / NOT_APPLICABLE 状态。严重门禁失败不得被其他维度高分抵消。

| 门禁 ID | 检查内容 | 评价路径 |
|---|---|---|
| G01 | 来源身份真实、可定位、引用与来源映射一致 | IDA |
| G02 | 任务与声明的目标能力/行为构念一致 | IDA |
| G03 | 任务在规定输入、权限和环境条件下可解或可合理审查 | IDA |
| G04 | Ground Truth / Oracle 有可信依据且经过独立核验 | IDA / ERA |
| G05 | Rubric 评分主体、通过/失败条件和证据要求一致、可观察 | IDA |
| G06 | 安全、权限、隐私、副作用和清理要求适当 | IDA / ERA |
| G07 | 数据完整性、泄漏、答案暴露和误导性标签得到审查 | IDA / ERA |
| G08 | 运行环境、工具、版本、轨迹和判定证据可审计 | ERA |

UNKNOWN、NOT_RUN 和 NOT_ASSESSED 不能解释为 PASS。门禁不适用时必须说明理由。

## 3. 独立离线评价（IDA）

IDA 不运行被测 Agent。它应至少形成以下分项画像：

- **构念与目标对齐**：目标是否有操作性定义；任务是否测量目标能力而非无关能力。
- **任务有效性**：清晰度、可解性、前置条件和约束是否明确。
- **来源与 Ground Truth**：来源真实性、引用定位、主张支持和参考结果正确性。
- **Rubric 与可判定性**：评分主体一致、通过/失败条件完整、可接受变体和 UNKNOWN 处理明确。
- **覆盖与代表性**：覆盖范围全集、适用性、关键缺口、场景分布及来源分布。
- **多样性与冗余**：语义重复、模板重复和样本增量信息。
- **泄漏与独立性**：数据污染、答案暴露、调优集和保留集独立性。
- **执行准备度与维护**：工具、权限、环境、状态重置、清理、版本和变更追溯。

可使用确定性校验、原始来源核验、专家盲评和受控反事实审查。必须标明每项证据类型。Schema PASS 不等于语义有效；引用可解析不等于来源支持主张。

IDA 不得伪造 Agent 难度/区分度、真实 Judge 准确率、真实故障检出率、重测 ICC 或执行成本。这些需要 ERA 数据。

## 4. 真实环境运行评价（ERA）

ERA 必须绑定：
- 符合 Skill 随包提供的 Runtime Record Schema 的逐次运行记录；
- 数据集版本与 SHA-256；
- Agent / Skill 版本与提交；
- 模型标识和版本；
- Harness、工具版本；
- 环境版本/镜像摘要；
- 执行参数、随机种子和运行协议；
- 原始轨迹、结果产物和判定证据。

### 4.1 评分器有效性

使用独立 Gold / Oracle 样本审查：
- False Pass / False Fail；
- Judge 与人工/Oracle 的一致性；
- UNKNOWN / Abstention；
- 重复评分一致性；
- 位置、格式、措辞等偏差；
- 评分器对反事实变化的敏感性。

高重测一致性不能证明无偏或有效。必须同时报告混淆矩阵、类别基率、适用范围和置信区间。

### 4.2 Capability Evaluation

根据 Agent × Task 响应数据，按模型假设选择 IRT、Bootstrap、层级模型或 Generalizability Theory。适用时报告：
- 任务难度和区分度；
- 测试信息函数和条件测量误差；
- 能力估计与排名不确定性；
- 跨模型、工具、语言和任务域的测量不变性/DIF；
- 与独立任务或已知组的外部关系。

IRT 只有在模型拟合、局部独立、参数可识别性和样本条件得到支持时才使用。难题不自动等于好题。

### 4.3 Regression Evaluation

应使用同任务、同环境、配对协议比较版本，并分别报告：
- 历史真实故障回放检出；
- 非等价变异缺陷检出；
- False Pass / False Fail；
- 任务级新旧版本差异；
- 失败暴露和故障诊断；
- Agent、环境和 Judge 的重复运行波动；
- 执行时间、Token、工具调用和成本。

Mutation Score 不得代替真实故障检出。总体平均分不得掩盖关键任务退化。

## 5. 指标与报告

机器可读指标定义见本仓库开发资产中的候选指标字典。报告至少包括：
- 每项指标的操作性定义、单位、分子/分母；
- 状态、证据引用、限制和适用范围；
- 置信区间或不确定性；
- 不适用、未评估、未运行和未知的原因；
- 关键门禁结果与发现问题；
- IDA / ERA 的分离结果。

比例指标报告分子、分母和区间。分母为零时使用 NOT_APPLICABLE，不得返回 0。证据不足时使用 NOT_ASSESSED / UNKNOWN，不得以零分代替。

## 6. 综合分、权重与阈值

**当前标准不提供已验证的通用综合分、固定权重或通过阈值。**

v0.0.1 的固定权重和等级阈值没有足够的独立效度证据，不作为 v0.0.2 的已验证公式继承。

候选聚合模型可包括加权算术、几何、非补偿瓶颈、分层或用途特定模型。任何模型都必须通过：
- 构念定义和专家内容效度；
- 评分过程与评分者一致性；
- 受控缺陷注入；
- 独立外部效标；
- 冻结验证集；
- 权重、标准化和缺失处理敏感性分析；
- 跨 Agent / Skill、任务域、模型和环境的适用性验证；
- 错误放行/误拒绝后果分析。

在验证报告支持之前：
- composite.status 必须为 NOT_VALIDATED 或 NOT_COMPUTED；
- composite.value 必须为 null；
- 不得显示 A/B/C 等级或伪精确总分；
- 输出多维画像、门禁和证据充分性。

公式只有在明确范围内通过独立验证后，才可标记 VALIDATED_FOR_SCOPE。不得把范围内有效宣称为普遍有效。

## 7. 证据充分性

证据充分性与数据集质量分数分开报告：
- sufficient_for_scope：证据足以支持明确范围内的判断；
- partial：只有部分维度/用途/范围有证据；
- insufficient：关键证据缺失或不可靠；
- not_assessed：尚未执行评价。

不得用“证据充分”替代质量结果，也不得用高质量分数掩盖证据不足。

## 8. 状态语义

- PASS：已执行且满足预先定义条件。
- FAIL：已执行且不满足条件。
- MEASURED：已计算描述性统计，但没有足够依据将其判定为质量通过或失败。
- UNKNOWN：存在不确定性，无法判定。
- NOT_RUN：尚未执行。
- NOT_ASSESSED：未评价。
- NOT_APPLICABLE：经说明后不适用。
- NOT_VALIDATED：候选公式/参数/阈值没有足够独立验证证据。
