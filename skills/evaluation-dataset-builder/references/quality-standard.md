# 高质量评测数据集标准

**标准版本：** 1.0.0  
**用途：** 评测数据集的设计、审查、修复和验收。

高质量数据集必须适用于明确的评测目的，有可信证据作为依据，覆盖重要场景，能够使用可靠的评分器判定，并且可以维护。用例数量本身不代表质量。

## 质量维度与权重

每项按 1–5 分评分。所有分数都必须有证据支持。证据不足时使用 `not_assessed`，不得猜分。维度权重与机器可读标准 `quality-standard.yaml` 保持一致。

| 机器键 | 中文维度 | 权重 | 评价内容 |
|---|---|---:|---|
| business_fidelity | 业务贴合度 | 15% | 是否依据真实目标、权威规则，或明确标记的合成场景 |
| capability_alignment | 能力对齐度 | 15% | 是否测量声明的能力，而非无关知识 |
| scenario_coverage | 场景覆盖度 | 15% | 是否覆盖重要流程、变体、边界和任务类型 |
| risk_coverage | 风险覆盖度 | 15% | 是否覆盖相关失败、安全、隐私、权限和高影响场景 |
| case_validity | 用例有效性 | 10% | 用例是否连贯、完整、可行且歧义足够少 |
| grader_reliability | 评分器可靠性 | 15% | 通过和失败条件是否明确、稳定且有证据 |
| diagnostic_power | 诊断能力 | 5% | 是否能定位能力或要求缺陷，并区分表现水平 |
| case_uniqueness | 用例独特性 | 5% | 是否避免语义重复和仅有模板差异的用例 |
| traceability_maintainability | 可追溯性与可维护性 | 5% | 是否记录来源、假设、版本和更新理由 |

评分锚点：1 分表示无效且有严重缺陷；2 分表示较弱且有重大缺口；3 分表示基本可用但有明确限制；4 分表示良好且主要要求均满足；5 分表示优秀且证据充分、没有已知重大缺陷。

## 用例级关键门禁

| 门禁 | 要求 |
|---|---|
| G1 证据与业务依据 | 不得包含无依据或存在冲突的预期行为 |
| G2 目标对齐 | 用例必须测量声明的评测目标 |
| G3 预期行为 | 预期行为必须明确且可判定 |
| G4 评分器有效性 | 判定条件合理，且具有可观察证据 |
| G5 安全与合规 | 不得违反适用的安全、隐私和合规要求 |
| G6 执行可行性 | 所需状态、工具、数据、权限和环境已提供或明确说明 |
| G7 数据完整性 | 不得存在严重重复、虚构来源或误导性标签 |

任何关键门禁失败，都不得仅依靠综合分数批准用例。

## 数据集级关键门禁

必须检查：

- 业务模型与来源映射是否可追溯。
- 覆盖矩阵是否有明确全集、适用性和缺口。
- 用例生成是否针对缺口并说明新增覆盖价值。
- 场景桶是否按适用性使用。
- 可观察断言是否足以判定关键行为。
- 混合来源是否区分真实案例与合成补缺。
- Agent、Skill 或工具的关键行为是否在适用时具备真实轨迹证据。
- 变更是否能定位受影响用例并完成局部修复和必要重测。
- 重要评测目标和必需能力是否已纳入规划，关键风险是否已覆盖。
- 数据集是否被近似重复用例主导，评分器是否针对预定用途完成校准。
- 覆盖声明是否对应明确定义的覆盖范围全集，预定用途是否与证据质量和数据独立性相符。

质量审查应独立于生成过程执行，不得只依赖生成者自评。

## 评分与处置

综合质量分 = Σ（维度得分 ÷ 5 × 维度权重）。所有维度权重之和必须为 100，并在报告中列出。综合分不能覆盖关键门禁失败。

| 等级 | 要求 |
|---|---|
| A / Approved | 所有关键门禁通过，综合分不低于 4.5，且满足覆盖要求 |
| B / Usable | 所有关键门禁通过，综合分不低于 3.8，且已记录限制 |
| C / Needs Improvement | 不存在数据完整性或安全性否决问题，但分数或覆盖不足 |
| Rejected | 存在未解决的关键门禁失败，或数据集存在实质性无效问题 |

## 评分器与治理

每个评分器必须定义判定标准、证据、通过和失败条件、可接受变体、UNKNOWN 处理、参考来源和校准方法。受约束的输出优先使用确定性检查；具有副作用的 Agent 使用状态或终态检查；开放式回答使用明确量表。使用正例、负例、边界例和对抗例校准评分器。自动形成的参考结果必须明确标注来源，并经过独立核验后才能作为高可信判定依据。

审查目标、能力、场景和风险覆盖；任务复杂度分布；来源分布；语义重复情况；评分器校准；执行就绪情况；独立留出集；来源追溯和维护计划。删除密钥和不必要的个人信息；区分真实来源数据和合成数据。对具有副作用的任务，定义隔离环境、重置、清理、允许操作和成本限制。记录标准、Schema、构建工具、来源、评测对象和数据集版本。未解决的用例必须标记为 `needs_info` 或 `rejected`。
