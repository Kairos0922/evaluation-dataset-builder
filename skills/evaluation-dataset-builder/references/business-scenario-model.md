# 业务场景建模规范

## 目的
在生成评测用例前，将业务资料整理为可追溯、可覆盖、可判定的业务模型。业务模型是场景规划和用例生成的中间产物，不是对缺失业务事实的补写。

## 建模对象
根据评测对象和资料选择适用字段；不适用字段标记为“不适用”并说明理由，不得为了填满模板而虚构内容。

| 字段 | 定义与要求 |
|---|---|
| model_id | 稳定的业务模型标识 |
| business_domain | 业务域及边界 |
| actors | 参与角色、身份和权限边界 |
| capabilities | 能力标识、能力描述及对应评测目标 |
| entities | 关键业务对象及其可观察属性 |
| lifecycle_states | 业务对象状态、合法转换和终态 |
| business_rules | 规则标识、规则内容、适用范围、优先级及来源 |
| workflows | 流程步骤、分支条件、依赖和异常路径 |
| operations | 可执行操作、前置条件、预期效果和副作用 |
| constraints | 配额、时间、格式、权限、资源和合规限制 |
| failure_modes | 已知或合理推导的失败模式；注明依据类型 |
| risks | 风险、影响、发生依据和风险处置要求 |
| observables | 可用于判定的输出、状态、工具调用、事件或副作用 |
| evidence_refs | 支撑模型内容的来源引用 |
| assumptions | 未确认假设及其影响范围 |
| unresolved_items | 冲突、缺失信息、待确认事项及责任角色 |

## 建模步骤
1. 从权威资料提取角色、能力、对象、规则、流程、状态和限制。
2. 为每项业务规则分配稳定标识，并记录来源、版本、生效时间、适用范围和可定位证据。
3. 将规则映射到能力、流程节点、状态转换、操作和风险。
4. 区分已确认事实、推断、合成示例和未知项；合成内容不得作为业务事实或金标准。
5. 标注每项规则可被什么外部可观察证据验证；不可观察的要求需要补充证据方案或标记为不可判定。
6. 识别资料冲突、规则缺口和无法覆盖的业务路径，形成待确认清单。
7. 将模型映射到场景全集和覆盖矩阵，再据覆盖缺口生成用例。

## 规则与场景映射
每条场景至少关联一个能力或评测目标；有业务依据时关联规则、流程节点、状态转换、角色/权限和风险。场景映射应能回答：
- 该场景验证哪项能力或业务规则？
- 触发条件、前置状态和关键输入是什么？
- 预期状态变化或可观察结果是什么？
- 哪些行为必须禁止，哪些副作用需要检查？
- 依据来自哪里？是否存在假设或冲突？
- 该场景与已生成用例相比，新增了什么覆盖价值？

## 适用边界
对纯文本问答、无状态工具或资料不足的任务，可以采用简化模型，仅保留目标、能力、规则/依据、输入条件、预期行为和可观察证据。不得强制构造不存在的业务实体或状态机。
