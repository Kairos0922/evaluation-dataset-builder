# 宿主 Agent 能力适配规范

## 目的

本 Skill 不自带工具运行环境。实际执行能力由宿主 Agent 提供。本规范要求在任务开始时识别可用能力，并根据实际能力安排工作。

## 能力识别

根据当前会话和宿主环境可见的信息，确认以下能力是否可用：阅读用户提供的文件和资料；搜索用户授权访问的知识来源；读取仓库、代码或结构化数据；创建、编辑和校验文件；执行代码或本地命令；访问网络或外部接口；在受控环境中调用工具并观察结果；保存任务进度、检查点和执行证据。

不得根据其他宿主环境的经验推断当前环境具有某项能力。不得自行假设凭证、权限、文件路径或网络访问已经配置。

## 能力使用规则

1. 先确认能力存在，再安排依赖该能力的操作。
2. 只在用户授权范围和宿主权限内执行操作。
3. 对可能修改数据、创建资源、发送消息或产生费用的操作，遵守宿主确认机制和安全约束。
4. 记录实际使用的能力、输入、结果和失败信息。
5. 不得将计划执行或准备执行描述为已执行。
6. 不得伪造工具结果、运行 ID、日志、状态快照或外部来源。
7. 不要求用户重复提供已经在当前任务中可访问的资料。

## 能力不可用时的降级

能力不可用时，说明缺少的能力及其影响；将受影响的事项标记为 BLOCKED 或 NOT_RUN；继续完成不依赖该能力的资料分析、用例设计、Schema 检查和文档准备；提供恢复执行所需的具体条件；不得用模拟结果冒充真实执行证据。

如果缺失能力会影响部分用例，不得因此阻断全部独立用例。

## 长任务与检查点

对多阶段任务，将任务划分为可独立检查的阶段；为每个阶段记录输入、输出、状态和未解决问题；阶段完成后保存已验证结果；恢复任务时先检查已完成内容，只补做缺失或失效的部分；输入资料、规则版本或执行环境发生变化时，判断哪些结果失效并安排重测。

不得在未确认前置阶段结果时跳过依赖步骤。不得无限重试已明确失败的操作。

## 能力声明

最终报告应区分已使用且成功的能力、已尝试但失败的能力、当前不可用的能力和尚未尝试的能力。只对实际观察到的结果作出结论。
