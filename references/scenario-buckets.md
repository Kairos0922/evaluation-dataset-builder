# 场景分类与用例桶规范

## 使用原则
场景桶用于检查遗漏，不是要求每个数据集机械填满所有类别。先根据评测目标和业务模型判断适用性；对不适用类别记录理由。一个用例可以具有多个标签，但覆盖统计必须明确采用“用例数”还是“独立覆盖项数”，不得重复计数。

## 场景桶
| 机器标识 | 场景类别 | 典型检查点 |
|---|---|---|
| normal | 正常流程 | 常规输入、合法状态、预期主路径 |
| boundary | 边界条件 | 最小/最大值、空值、长度、阈值、临界状态 |
| business_rule | 业务规则 | 规则约束、优先级、条件分支、规则组合 |
| permission_security | 权限与安全 | 身份、授权、越权、敏感信息、策略限制 |
| state_anomaly | 状态异常 | 缺失状态、非法转换、过期或不一致状态 |
| error_recovery | 错误与恢复 | 超时、失败重试、部分成功、回滚、补偿 |
| multi_turn | 多轮交互 | 上下文延续、澄清、纠错、跨轮约束 |
| tool_interaction | 工具交互 | 工具选择、参数、调用顺序、结果处理 |
| negative | 负向与拒绝 | 不满足前置条件、不可执行请求、拒绝条件 |
| adversarial | 对抗场景 | 注入、诱导绕过、冲突指令、恶意输入 |
| data_quality | 数据质量 | 缺失、冲突、过期、格式异常、来源不可信 |
| integration | 集成与契约 | API 契约、跨系统依赖、幂等、事件一致性 |

## 选桶步骤
1. 从业务模型和评测目标确定适用桶。
2. 将已知事故、历史缺陷、用户反馈和风险登记映射到对应桶。
3. 为每个适用桶定义至少一个可验证的覆盖目标；高风险桶需覆盖关键变体。
4. 对不适用桶说明依据，不能仅因生成成本高而标记不适用。
5. 生成后按桶检查覆盖缺口和重复情况。
6. 用例必须同时保留业务场景标签；场景桶不能替代业务场景本身。

## 风险与优先级
优先级综合考虑业务影响、风险严重度、已知发生证据、能力不确定性、覆盖缺口、诊断价值和执行成本。高风险或已知故障场景优先；低价值措辞变体不应挤占关键覆盖预算。
