# 评测覆盖设计规范

## 先定义覆盖范围全集

在生成用例前，定义有限、可解释且与评测目的对应的覆盖范围全集，并形成覆盖矩阵。每个覆盖项至少包含稳定标识、维度、取值、适用性、业务依据/来源、风险或重要性、当前覆盖状态和缺口说明。

可选维度包括：评测目标/能力、业务规则、流程节点/状态转换、场景桶、角色与权限、输入条件、风险/失败模式、工具/API/环境、任务复杂度、来源类型和执行条件。根据对象选择适用维度；不适用时记录理由。不得把未提供的数据或未经核实的假设描述为已覆盖事实。

## 业务模型先行

先将业务资料整理为角色、能力、实体、状态、规则、流程、操作、约束、风险、失败模式和可观察证据，再映射到覆盖矩阵。具体建模方法见 `business-scenario-model.md`。资料不足时采用简化模型，不虚构业务实体或规则。

## 场景桶检查

使用 `scenario-buckets.md` 中的分类检查遗漏。场景桶不是强制配额；只纳入适用类别，并说明不适用理由。已知事故、历史缺陷、用户反馈和风险应映射到具体覆盖项。

## 缺口驱动生成

1. 先识别已覆盖、未覆盖、部分覆盖、待确认和不适用的覆盖项。
2. 对每个缺口说明影响、依据、风险、诊断价值、生成成本和依赖条件。
3. 按优先级生成用例：关键风险/安全与权限缺口、已知故障、核心业务规则与主流程、边界与异常恢复、能力不确定性、低风险补充项。
4. 每次生成应说明它覆盖哪些缺口，以及相对现有用例新增的覆盖价值。
5. 若候选用例无法补足缺口，记录阻断原因和所需证据；不得以措辞变体虚增覆盖。
6. 不盲目生成维度的笛卡尔积；先覆盖关键组合，再依据风险和缺口补充。

## 缺口优先级

建议采用可解释的定性分级，必要时使用显式权重。至少考虑：
- 业务影响与风险严重度；
- 已知发生证据（事故、缺陷、反馈、轨迹）；
- 评测目标的重要性和能力不确定性；
- 当前覆盖缺口及该用例的诊断价值；
- 执行可行性、依赖和成本。

优先级不是伪精确概率。缺少可靠频率数据时，不得编造发生率或统计显著性。

## 覆盖统计

覆盖报告必须说明：
- 覆盖范围全集及纳入/排除理由；
- 每个维度的覆盖项总数、已覆盖数、覆盖率、未覆盖项和缺口原因；
- 覆盖率分子、分母和计数口径；
- 高风险覆盖情况及证据；
- 适用/不适用项的判定依据；
- 多标签用例的去重计数方式；
- 尚待确认、因证据缺失或执行条件不足而未覆盖的项目。

覆盖率 = 已覆盖的适用覆盖项数 ÷ 适用覆盖项总数。分母为 0 时标记为不适用，不计算百分比。不得把待确认项算作已覆盖；不得把一个用例覆盖多个标签时重复计入用例总数。
