# v0.0.2 需求规格：通用 Agent / Skill 评测集质量评价

- 目标版本：0.0.2
- 状态：需求基线与工程架构/验收解释基线已冻结（D-007）；发布验收仍待完成
- GitHub Issue：[#43](https://github.com/Kairos0922/evaluation-dataset-builder/issues/43)
- 适用对象：通用 Agent / Skill
- 评测用途：Capability Evaluation 与 Regression Evaluation

## 1. 背景与问题

v0.0.1 已具备评测集生成、Schema 校验、来源追溯、覆盖矩阵、用例判定契约和质量审查规范。但现有质量标准使用九个维度、固定权重、1–5 分制及 4.5 / 3.8 等级阈值。仓库尚无证据证明这些权重和阈值经过独立专家效度、外部效标、缺陷注入或敏感性验证。

因此，v0.0.2 不得将 v0.0.1 综合分数继续描述为经过科学验证的质量测量。必须重建测量定义和验证证据，并保留已有可验证的结构与来源规则。

## 2. 目标

1. 建立可审计的评测集质量测量构念、指标定义和证据模型。
2. 建立不运行被测 Agent 的独立质量评价方法。
3. 建立真实环境运行后的实证评价方法。
4. 分别支持 Capability 与 Regression 两种用途。
5. 研究并验证量化公式；只有通过预先定义的验证协议，才允许将综合分标记为 validated。
6. 将任务、状态、决策、代码、测试、实验数据和发布证据持久化在 GitHub。

## 3. 非目标

- 不承诺一定能构造出单一通用 0–100 分。
- 不将所有质量维度强制映射为同一潜变量。
- 不将 Agent 表现分数当作数据集质量分数。
- 不将 Schema 通过、LLM 自评、生成者自评或静态检查通过等同于效度证明。
- 不以主观权重、AHP 专家偏好或固定样本量代替经验验证。
- 不把某个领域 Benchmark 的指标比例直接推广到所有 Agent / Skill。
- 不修改或关闭 Builder 证据 PR #38，不重复运行其已完成的 Builder、Pilot、Oracle 证据。

## 4. 需求边界

### 4.1 评测对象

通用 Agent / Skill。指标定义必须避免绑定单一模型供应商、Agent 框架、工具协议、业务领域或运行宿主。领域特定检查允许作为可插拔模块，但必须声明适用范围。

### 4.2 评测用途

- Capability Evaluation：测量目标能力水平、能力差异、能力短板及测量不确定性。
- Regression Evaluation：在版本、配置或环境变化前后，发现已知行为退化、新失败模式和关键约束回归。

两种用途共享部分数据质量与评分器质量要求，但统计目标、样本选择、重复运行和决策指标必须分开定义。

### 4.3 两类质量评价

**A. 独立 / 离线质量评价**

不执行被测 Agent。评价数据集设计和内容本身，包括目标定义、构念对齐、任务可理解性、任务可解性证据、来源可靠性、Ground Truth、Rubric、可观察判定条件、覆盖设计、重复/独立信息、适用性、数据污染与维护信息。

离线评价必须区分：
- 可由机器确定的结构/完整性检查；
- 基于来源和规则的证据核验；
- 需要领域专家的语义/构念审查；
- 只有真实运行才能获得的指标（不得在离线评价中伪造）。

**B. 真实环境运行评价**

在记录 Agent/Skill 版本、模型、工具、环境、提示、运行参数、随机种子、执行协议和数据集 SHA 的条件下执行。评价实际测量效力、评分器准确性、重复性、错误暴露能力、统计不确定性、跨配置稳健性及执行成本。

必须区分 Agent 随机行为、环境随机性、Judge 随机性和数据集本身的问题。

## 5. 量化与公式要求

1. 每个指标必须有操作性定义、单位、计算式、分母/分子、输入证据、缺失值处理、适用条件和局限。
2. 对指标进行构念映射，说明它是形成性指标、反映性指标、结果指标、门禁还是诊断指标。
3. 评估指标间相关性、冗余、交互、补偿性及潜在重复计量。
4. 比较多种候选聚合模型，不预设加权算术平均、几何平均、最小值或其他模型必然正确。
5. 权重必须有明确的理论/经验来源，并进行权重不确定性和敏感性分析。
6. 阈值必须基于用途相关的错误成本、外部效标、统计功效和独立验证结果确定，不得沿用未经验证的固定数值。
7. 严重正确性、安全、来源真实性和评分器错误等关键问题必须采用非补偿性处置，不能被其他维度高分抵消。
8. 分数必须与证据充分程度分开报告。
9. 若证据不支持有效的单一总分，产品必须输出多维画像、门禁和未验证状态，不得强行合成。

## 6. 验证与证明要求

“公式有效”指公式支持特定解释和决策的效度证据成立，而不是公式可以计算或数学形式优雅。

至少研究并设计以下证据：

- 内容证据：专家判断指标是否覆盖目标质量构念。
- 反应过程证据：审查者、Judge、验证器是否按预期理解并应用规则。
- 内部结构证据：指标结构是否符合提出的测量模型；不默认使用 Cronbach's alpha。
- 与其他变量关系的证据：质量指标是否与真实缺陷检出、历史故障回放、专家独立判断和测量精度存在预期关系。
- 后果证据：基于评分作出的质量决策，其误放行/误拒绝代价是否可接受。
- 评分者一致性：独立评审者之间的一致性及不确定性。
- 外部效度：跨 Agent、Skill、任务领域、模型、工具与环境的泛化。
- 稳健性：缺失值、权重、归一化、抽样、重复任务和评分方法变化下的结果稳定性。
- 反证检验：对数据集注入已知缺陷，检验指标是否能识别缺陷；对有效样本做控制变更，检验是否避免误报。

所有验证集必须与指标/权重开发数据隔离；冻结协议、数据版本、代码版本和分析计划。

## 7. 交付物

- 需求与决策记录。
- 研究证据库及来源等级、适用性和局限。
- 独立评价与真实运行评价的方法论。
- Capability 与 Regression 用途专属统计方案。
- 候选公式比较、公式选择依据和验证报告。
- JSON Schema / 报告契约、可调用验证器、测试与样例。
- 更新 Skill 质量标准与引用。
- 持久化任务跟踪、变更日志、CI 证据、验收报告和 v0.0.2 Release。

## 8. 验收标准

- 每个质量维度和指标可追溯到定义、证据、计算实现及测试。
- 静态评价不会把未运行的指标标为 PASS。
- 运行评价能区分 Agent、环境和 Judge 的误差来源。
- Capability 与 Regression 有各自的有效性论证和统计分析。
- 综合公式若要标记为 validated，必须通过冻结的独立验证协议；验证失败则不得发布为已验证公式。
- 权重、阈值若样本或证据不足，必须明确报告未确定，不得以默认值冒充科学结论。
- 任务清单每项完成后更新状态、commit、测试/实验和证据引用。
- 不覆盖或更改 PR #38 的既有历史证据和 Draft/Open 状态。
