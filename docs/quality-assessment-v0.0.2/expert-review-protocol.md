# 专家内容效度与盲评执行协议

**状态：** 可执行协议草案，尚未招募专家、收集评分或计算内容效度结果。任何统计量在实际评分数据到位前均为 NOT_RUN。

## 1. 目的与边界

本协议用于独立评价 Builder 生成的评测用例、目标构念、Ground Truth、Rubric 和关键风险覆盖。专家评审是 IDA 的语义证据来源，不是 Agent 能力评分，也不能单独证明预测效度或综合公式有效。

必须保持三条数据链分离：
1. Builder 原始输出与版本哈希。
2. 专家盲评原始记录。
3. 盲评后仲裁记录。

不得以仲裁结果覆盖原始盲评，不得将同一批专家数据既用于构建公式又称为独立外部效标。

## 2. 评审对象与抽样

### 2.1 评审单位

最小评审单位是一个冻结数据集版本中的一条用例。每条记录必须绑定：
- dataset_id、dataset_version、dataset_sha256；
- item_id、item_sha256；
- reviewer_id（匿名伪名）；
- review_round、review_stage；
- rating_dimension、rating_scale、rating；
- rationale、evidence_refs、missing_evidence；
- protocol_version、protocol_sha256、reviewed_at。

记录契约：`schemas/expert-review-record.schema.json`。

### 2.2 专家遴选

专家组成要覆盖目标构念，而不是只按人数凑齐。至少记录：
- 角色：领域专家、Agent/Skill 实践者、评测工程师、学术研究者、安全审查者等；
- 专长领域；
- 相关工作经验区间；
- 利益冲突披露或回避状态。

Builder 作者、数据集作者或直接参与候选公式设计的人，不应作为该数据集的唯一独立评审者。若其参与，应标注利益关系，并将其评分与独立专家评分分开报告。

不设跨领域通用专家人数。评审人数由构念异质性、用例数量、风险等级、评审成本和目标区间精度共同决定。若评审人数较少，应明确报告小样本不确定性，不得使用某篇研究中的经验 cutoff 作为本项目通用门槛。

### 2.3 评审覆盖设计

- 用例量可控时，每位专家评审全部用例，以便估计同一对象上的评分者一致性。
- 用例量过大时，可采用按构念、风险、任务类型分层的平衡不完全区组设计；必须保留共同锚定用例，使评分者之间有可比较的重叠。
- 关键安全、授权、Ground Truth 和不可逆副作用用例，不得因抽样而完全缺少独立审查。
- 记录每个条目的实际评审人数；不同条目不可默认具有相同分母。

## 3. 盲评流程

### 阶段 A：冻结与预注册

1. 冻结数据集、用例、Manifest、Source Registry、Rubric 和全部文件哈希。
2. 冻结构念蓝图、评审维度、评分锚点、统计方法和数据排除规则。
3. 预注册主要评审问题、主要统计量、置信区间方法、缺失值处理和仲裁流程。
4. 评审者不得看到 Builder 身份、Builder 自评、自动质量报告、候选综合分数、权重或其他专家评分。

### 阶段 B：独立盲评

1. 随机化用例顺序。
2. 专家独立评分，不讨论具体条目，不共享评分。
3. 每个评分必须附理由；关键判断需引用可复核的来源或证据。
4. 对无法判断的条目记录缺失证据，不得猜测或强行给出 PASS。
5. 记录 blind_status=true；盲评原始记录不可覆盖。

### 阶段 C：分歧分析与仲裁

1. 汇总原始分布、逐条分歧和一致性统计后，再组织讨论。
2. 仲裁可以查看证据和讨论合理解释，但必须保留原始评分。
3. 仲裁结果记录为独立 review_stage=adjudication 记录，标明 accepted、modified、rejected 或 needs_more_evidence。
4. 对仍存在合理分歧的条目保留多种解释；不能为了产生单一标签而消除真实不确定性。
5. 任何关键证据缺失或无法确认的条目，维持 UNKNOWN / NEEDS_INFO。

## 4. 评分维度与锚点

每个维度独立评分，不将不同维度合并成一个“专家总分”。

| 维度 | 4 点量表锚点 | 主要问题 |
|---|---|---|
| relevance | 1 无关；2 弱相关；3 相关；4 高度相关 | 用例是否测量声明目标 |
| representativeness | 1 严重偏离/遗漏；2 代表性有限；3 代表性充分；4 能覆盖构念关键方面 | 是否代表目标构念范围 |
| clarity | 1 无法明确解释；2 存在关键歧义；3 基本清楚；4 输入、约束和成功条件明确 | 不同执行者能否一致理解 |
| observability | 1 无法复核；2 证据薄弱；3 有可定位证据；4 可独立复现和审计 | 结果能否被外部检查 |
| construct_alignment | 1 测量错误构念；2 主要测量其他能力；3 基本对齐；4 与构念蓝图高度一致 | 任务与构念映射是否成立 |
| task_solvability | 1 不可解；2 缺少关键条件；3 在声明环境下可解；4 可解且前置条件可审计 | 是否存在可执行路径 |
| ground_truth_support | 1 无依据/冲突；2 支持不充分；3 主要结论有依据；4 每项关键判断均有独立证据 | 参考答案是否被来源/Oracle 支持 |
| rubric_alignment | 1 Rubric 与目标不符；2 有关键错配；3 基本匹配；4 每项标准均可观察且对齐 | 评分标准是否测量预期行为 |
| safety_authorization | 1 存在未授权高风险副作用；2 约束不足；3 权限边界明确；4 权限、停止和清理要求完整 | 是否存在授权和安全缺陷 |
| risk_coverage | 1 漏掉关键风险；2 覆盖不足；3 关键风险已覆盖；4 风险与任务/证据映射完整 | 关键风险是否被覆盖 |

### 必要性维度

necessity 使用三分类，不与四点量表混用：
- essential；
- useful_not_essential；
- not_necessary。

若评审者无法判断，记录 missing_evidence 和 rationale，不得擅自映射到“必要”或“不必要”。

## 5. 统计量与计算

设某条目有 N 位有效专家评分。

### 5.1 内容效度指数 CVI

对 relevance 维度的四点评分，评分 3 或 4 记为相关：
- I-CVI = 该条目评分 3 或 4 的专家数 / 该条目有效评分专家数。
- S-CVI/Ave = 所有条目 I-CVI 的算术平均。
- S-CVI/UA = 所有专家均给出 3 或 4 的条目数 / 有效评审条目数。

必须同时报告每条目的分子、分母和缺失数量。S-CVI/Ave 与 S-CVI/UA 反映不同性质，不能择优报告。

### 5.2 内容必要性比率 CVR

对 necessity 维度：
`CVR = (n_essential - N/2) / (N/2)`

其中 n_essential 是判断该条目为 essential 的有效专家数。CVR 不是相关性指标，也不能与 I-CVI 互换。不得将特定专家人数下的临界值直接当作通用项目门槛。

### 5.3 Aiken's V

对有序评分：
`V = Σ(r_i - l_0) / [N(c - 1)]`

其中 r_i 为评分，l_0 为量表最低分，c 为评分类别数。必须按维度分别计算，并说明量表、有效 N 和区间方法。Aiken's V 不能证明预测效度或评分者一致性。

### 5.4 评分者一致性

- 两位评分者的序数类别判断：可采用预注册的加权 Cohen's Kappa，并报告权重距离、混淆矩阵和原始一致率。
- 多位评分者或存在不平衡缺失：按数据结构考虑序数 Krippendorff's Alpha。
- 近似连续评分：只有在评分尺度与研究问题适用时才用 ICC；必须明确 Model、Type、Definition 和具体 ICC 形式。
- 不得在观察结果后挑选数值最高的统计量；Gwet AC1 等不同机会模型的系数只能作为预先说明的敏感性分析。

一致性不等于效度。高一致性可能只是所有评审者共同误解 Rubric。

## 6. 样本量、区间与统计功效

1. 对 I-CVI、CVR 等比例统计，报告原始分子/分母和适用的 Wilson 或精确二项区间。专家是目的性遴选而非随机抽样时，区间只描述本评审设计下的不确定性，不自动代表所有领域专家总体。
2. 对 Aiken's V、S-CVI/Ave 和评分者一致性，按专家与条目聚类结构规划 Bootstrap 或模型区间；不得把同一专家评审的多个条目当作完全独立样本。
3. 评审规模通过构念覆盖、专家异质性和目标区间宽度规划。可先用 Pilot 估计评分分布、缺失和评审者分歧，再用 Monte Carlo 模拟评审人数、条目数、区组重叠和方差结构对区间覆盖率/估计误差的影响。
4. 若主要目标是比较两个数据集/版本的内容效度差异，应预先定义最小有意义差异和决策风险，再按配对或分层结构做功效分析。
5. 若区间过宽、关键专家类别缺失或条目覆盖不足，结论为 EVIDENCE_INSUFFICIENT；不得用经验阈值掩盖样本不足。

## 7. 结果解释和决策规则

- CVI、CVR、Aiken's V 和一致性统计分别回答不同问题，不进行无依据的加权平均。
- 对关键安全、授权、Ground Truth 错误、不可解任务和严重 Rubric 错配，采用非补偿式风险说明；大量普通条目的高分不能抵消一个关键缺陷。
- 统计量不得单独决定保留/删除。决策还需结合理由、来源证据、任务用途、缺陷严重度和不确定性。
- 没有预注册的目标效应、误判代价和置信区间要求时，不设统一 PASS 阈值。
- 所有未解决的关键分歧和缺失证据必须进入报告。

## 8. 数据治理与交付

必须归档：
- 冻结数据集与逐条目 SHA-256；
- 评审协议版本与 SHA-256；
- 匿名专家构成、领域覆盖和利益冲突声明；
- 随机化顺序与评审分配；
- 逐专家原始评分和 rationale；
- 逐条目的缺失、分歧和仲裁记录；
- CVI、CVR、Aiken's V、一致性统计和区间；
- 排除规则、统计脚本版本和复现说明。

只存匿名 reviewer_id 和经验区间，不在评审数据中保存姓名、邮箱或其他直接身份信息。
