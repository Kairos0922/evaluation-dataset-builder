# 轨迹驱动任务发现操作手册（v0.0.3）

## 目的

本手册把真实 Agent 工作轨迹转化为可审查的评测任务候选。它不自动判断模型能力，也不要求任何宿主自动收集用户本地历史。

## 操作流程

### 1. 明确来源与授权

- 仅使用用户明确提供或明确授权的轨迹。
- 记录来源类型、导出时间、宿主/模型/Harness/环境身份、原始工件 URI 和 SHA-256。
- 先删除凭据、访问令牌、个人信息、专有业务信息和与任务无关内容。
- 授权范围、脱敏状态不清晰时停止导入；不得把“文件可访问”视为“已获授权”。

输出：`trajectory-source.schema.json` 对应记录。

### 2. 发现候选，不直接下结论

可用于定位的信号：
- 用户明确指出产出不理想；
- 同一任务发生返工，且产物有实质变化；
- 同一问题出现多轮交互或较长执行轨迹；
- 能定位某个具体决策及其后果；
- 输入、交付物和潜在判定条件可识别。

这些信号只用于候选排序。高交互轮数、长轨迹或用户不满本身都不能证明模型存在能力缺陷。

输出：`task-candidate.schema.json` 对应记录及原始事件引用。

### 3. 资格审查并归因

围绕关键错误决策发生前的信息回答：
1. 当时 Agent 实际可见哪些信息？
2. 这些信息是否足以合理地避免错误？
3. 是否有关键要求直到错误发生后才由用户补充？
4. 工具、依赖和环境当时是否健康？
5. 任务输入、交付物和质量标准是否明确？
6. 是否存在其他合理解释？

归因只能从以下类别选择：`agent_decision`、`missing_context`、`task_ambiguity`、`tool_failure`、`environment_failure`、`stochastic`、`mixed`、`unknown`。

证据不足时必须保留 `unknown`。只有错误可避免、任务契约明确、环境健康且证据充分时，才可将其作为已资格审查的候选能力缺口；这仍不是 Benchmark 有效性的最终证明。

输出：`failure-qualification.schema.json` 对应记录。

### 4. 切出最小但完整的任务

- 起点：任务关键决策之前，且已包含解题者应获得的全部初始上下文。
- 终点：足以观察交付物或关键错误后果的位置。
- 记录事件引用，不复制不必要的完整对话。
- 还原输入、文件/数据库初始状态、约束、权限和禁止副作用。
- 明确交付物与可判定标准；对开放式任务列出合理可接受变体。
- 进行提示泄漏审查，不能把事后纠偏、参考答案或关键解题步骤带入任务指令。

如果切片后任务无法独立执行、上下文不闭合或无法判定，应继续补充证据、重新切片或拒绝该候选，而不是强行造题。

输出：`task-slice.schema.json` 对应记录。

### 5. 声明环境重建

记录初始状态工件及哈希、依赖版本、工具契约、权限、网络策略、资源限制、超时、动作预算、重置和清理步骤，以及与原始环境的差异。

不得自动重放原始轨迹中的命令或副作用。默认使用隔离、最小权限、禁网或白名单环境。环境重建 Manifest 是声明，不等于环境已成功构建或已通过健康检查。

输出：`environment-reconstruction.schema.json` 对应记录。

### 6. 独立运行与验证

- 冻结任务、数据、Agent、模型、Harness、工具、环境、seed 和执行协议。
- 使用干净上下文的新会话执行，不继承原始 session 的隐藏状态。
- 按预注册设计决定模型数和重复次数，不设无证据的统一次数。
- 通过独立 Verifier / Oracle 判定；参考答案不得由 Builder 单独生成并自我认证。
- 检查假阳性、假阴性、UNKNOWN、合理变体和环境故障。
- 阅读完整轨迹，区分规划、关键决策、工具调用、结果检查、返工和成本。

无真实运行、无独立 Gold 或证据不足时，分别记录 NOT_RUN / NOT_ASSESSED / UNKNOWN；不得用结构校验通过替代实证结论。

## 轨迹诊断信息的使用边界

失败阶段、关键决策、错误传播、纠偏次数、工具调用和成本首先是诊断信息。只有在明确构念、测量单位、分母、独立效标和可靠性证据后，才考虑将某项信息升级为正式评价指标。不得因数据容易采集就增加评分项或合成总分。
